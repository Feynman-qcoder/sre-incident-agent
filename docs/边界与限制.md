>
> **知道系统看不见什么，与看得见什么同等重要**——下表每行均有注入实测或守护测试背书。

## 能力边界

| 边界 | 实证 | 现状 |
|---|---|---|
| 高基线服务（p99 恒顶格） | 009：注入 1200ms 后 ratio ≈ 1.0x，相对跳变规则失明 | 解法方向：SLO 燃烧率语义 |
| 低流量服务（0.004 req/s） | 010：直方图全 NaN | **absent 告警已补盲**（触发时延 ≈ 15 min = staleness 5m + 窗口 10m） |
| 秒级容器事件 | 007：重启间隙 < 30s 采集粒度，零告警 | 事件直推（watch 机制）= 已评估的方向 |
| 网络层故障（请求未到达） | 003 / 011：不落 SERVER span | CLIENT span 规则已实现（基线复验待环境恢复） |
| 中断恢复粒度 | `tests/test_recovery.py` 四用例守护三层语义 | 断点续跑刻意不做（单次 30s，重试成本更低） |
| 自动修复 | 无 write 权限工具 | 刻意设计：blast radius 不可控前不做 |

## 后续方向

按**触发条件**排期，不为技术先进性排期：

| 方向 | 触发条件 |
|---|---|
| SLO 燃烧率告警 + K8s 事件直推 | 补上表前两条边界 |
| checkpointer 断点续跑 | 单次调查耗时 > 5 分钟（性价比翻转点） |
| API / Worker 解耦与水平扩展 | 告警量超出单进程处理能力 |
| OTel 自观测（Agent 自身遥测） | 需要长期运行数据支撑调优时 |
